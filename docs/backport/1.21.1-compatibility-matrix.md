# Minecraft 1.21.1 rendering compatibility matrix

This matrix records Phase A/B findings for the Yarn `1.21.1+build.3` backport. The primary evidence is the mapped source and bytecode generated locally by Loom 1.17.14 under `.gradle/loom-cache/minecraftMaven`. Runtime-only compatibility claims remain explicitly unverified.

## Verified 1.21.1 ordering and material behavior

- `LivingEntityRenderer.render` renders the base model before iterating its `features` list. The pass-through observer runs at method HEAD and leaves that order untouched.
- Features execute in list order. Armor renders chest, legs, feet, then head. Armor layers, trim/decal selection, and glint issue separate model renders with distinct `RenderLayer` and `VertexConsumer` instances.
- Eye features obtain an emissive/eyes `RenderLayer` and render the context model with full-bright light.
- Invisible-but-visible-to-player entities use `RenderLayer.getItemEntityTranslucentCull` for the base model.
- `VertexConsumerProvider.Immediate` keeps configured layer buffers pending. When a pending layer is translucent, it calls `BuiltBuffer.sortQuads` before `RenderLayer.draw`.
- These facts rule out Phase C reordering of translucent, armor, eye, trim, glint, or overlay renders without additional ownership and ordering proof.

## Potential pure-Java reuse for later phases

The following 26.2 concepts are candidates for sharing after their Minecraft dependencies are separated: stable primitive submission planning, batch metric math, generation counters, backend state transitions, fallback/suppression policy, runtime configuration coordination, and instance-range calculations. Exact batch keys and planner records currently contain version-specific render objects, so they need adapters rather than direct copying. No shared-module refactor was performed in Phase A/B.

## Evidence commands and sources

- `./gradlew dependencies compileClientJava` resolved Minecraft 1.21.1, Yarn build 3, Loader 0.16.14, and Fabric API 0.116.14+1.21.1.
- `./gradlew genSources` generated the mapped common and client source jars.
- `javap -s -p` verified the `GameRenderer.render`, `LivingEntityRenderer.render`, and `ModelPart.render` descriptors.
- Inspected mapped sources: `GameRenderer`, `LivingEntityRenderer`, `FeatureRenderer`, `ArmorFeatureRenderer`, `EyesFeatureRenderer`, `EntityModel`, `Model`, `ModelPart`, `MatrixStack`, `VertexConsumer`, `VertexConsumerProvider`, `RenderLayer`, `VertexBuffer`, and `ShaderProgram`.
- Inspected remapped Fabric API sources for client connection events and synchronous resource reload listeners.
